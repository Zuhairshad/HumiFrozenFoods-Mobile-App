# App review: money and state paths

Independent review of `src/**` against `docs/api-contract.md` (sections 2, 3.2, 7) and `docs/DESIGN-V2.md` 5.5-5.8. Nothing here was run on a device. `tsc`, `eslint` and `vitest` are green after the fixes (16 files, 185 tests). New tests live in `tests/review/`; one existing test (`checkout-machine.test.ts`, double-tap) was adjusted to the new contract.

Counts: High 2 (1 fixed, 1 open), Med 6 (4 fixed, 2 open), Low 9 (2 fixed, 7 open).

## Checked and found correct

- `http.ts`: POST only retries with an `Idempotency-Key`, and every retry reuses the same key; GET retries 2x; `Retry-After` honoured up to 10 s then surfaced; timeouts and caller aborts distinguished; no body-less 2xx accepted; error envelope parsing tolerant of non-JSON.
- Idempotency key: stable across double-tap, cancel, decline and network retries; rotated only when the canonical body (lines, promo, contact, address, slot, notes) changes; `idempotency_key_reuse` handled once.
- Price check: totals compared after the intent is created and before the sheet opens; mismatch shows the server total and nothing is charged; retry reuses the intent.
- Cancelled vs failed vs declined mapped correctly; cancelled returns quietly. Client never sets `paid`: records `pending` (or `demo`), only `GET /v1/orders/:id` can change it.
- Cart is cleared only in the `succeeded` branch of `checkout.tsx`, followed by `router.replace`; back gesture disabled on checkout while busy and on the confirmation screen; `usePreventRemove` released before navigation, so the payment screen cannot be revisited and paid twice.
- Poller (`order-polling.ts`): aborts on unmount, errors count as attempts, 401/403 stop it, settled on first non-pending status.
- Quote reducer discards responses for older request keys; abort on supersede; empty cart resets; promo rejected by the server is dropped and its message shown.
- Money: no pounds/pence mix-ups found. Wire values are integer pence; `/100` appears only at display (`formatPrice`, `SummaryRows`, `CheckoutBar`); `order-mapping` uses `Math.round(p)/100`; `poundsToPence` rounds at the pence. `toFixed` only in rating labels and the machine's fallback formatter.
- Quantity limits 1-20 enforced in the store (`clamp`) and stepper; server `unavailable` reasons block the checkout button and the Pay action; the quote is required (not an estimate) before paying in live mode.
- Persist stores: cart/orders/favourites migrations are idempotent and tested; catalog `merge` validates stored products; guest tokens are kept out of the persisted orders snapshot (SecureStore with AsyncStorage fallback) and legacy inline tokens are moved.
- Enquiries: honeypot always empty, 400 field paths mapped, 429 text, network vs server errors; submit guarded by phase. Lookup: 404 collapsed to one message (no enumeration), rate-limit and offline handled.
- Accessibility of the pay flow: `Button` and `PressableScale` announce `disabled`/`busy`; Pay label becomes "Processing payment"; error alerts are native; unavailable/error text uses live regions.
- Error messages: unknown/non-API errors show a generic message; API messages come from the server envelope.
